# iOS accelerator ABI observation on A5XELTE

Patch `0141-a5xelte-ios-accelerator-abi-observation.patch` adds bounded,
opt-in diagnostics. It does not register an `IOAcceleratorES`, `IOGPU`, or
Metal service. The current Mali T720 queue accepts Midgard jobs generated by
the port; it cannot execute the Apple AGX command stream.

## Evidence and present boundary

- The staged iOS 16.7.16 `AGXMetalA11.bundle/Info.plist` names executable
  `AGXMetalA11` and principal class `AGXPrincipalDevice`. These are Apple A11
  graphics components, not a Mali userland backend.
- The existing `a5metalprobe=1` boot argument observed
  `matching IOAcceleratorES result=0`. Patch 0141 adds the requesting process
  name to that line, still capped at 64 lines per boot.
- XNU already has a SWEET IOKit trace for matching dictionaries,
  notifications, registry paths, and user-client opens. Patch 0141 enables
  this trace for A5XELTE with `sweetiolog=backboardd,SpringBoard`. It is off
  by default on A5XELTE and capped at 128 lines per boot. The trace records
  names, selector-independent open types, and return codes; it never records
  method payloads or creates a GPU user client.

The trace can identify which process asks for `IOAcceleratorES`, how it
matches the service, and which connection type it opens once a compatible
provider exists. It cannot reveal the full private method ABI while the
service is absent. A successful `IOAcceleratorES` match alone would not prove
that an iOS frame was rendered on Mali.

## Contract required before advertising acceleration

| Boundary | Current port | Required proof |
| --- | --- | --- |
| Discovery and open | No iOS GPU service; opt-in traces only | Actual target process opens a provider and receives a supported user client |
| Resource ownership | Bounded IOSurface tile import into private GPU backing | Pinned, validated, lifetime-managed IOSurface resources accessible to the GPU |
| Commands | Private Midgard fixture | iOS-facing command/resource API translated into valid Midgard jobs |
| Completion | Private fence and pixel comparison | Per-client fence, fault, and teardown semantics compatible with userland |
| Display | CPU-backed IOSurface-to-DECON path | Real iOS-generated GPU frame reaches scanout with verified pixels and sustained improvement |

Do not make a dummy service report `IOAcceleratorES` or `IOGPU` support.
`AGXMetalA11` emits Apple-specific operations, so such a provider would cause
false capability detection and likely failures. A functional path needs a
Mali-compatible userland graphics backend and its matching kernel ABI, or a
separate proven translator for the actual iOS requests.

No IPSW, extracted Apple binary, device log, or proprietary firmware is
committed with this note.
